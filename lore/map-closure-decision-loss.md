# 地图关闭时的决策流失

## Current conclusion

在这个仓库里，wayfinder 票的决议正文只存在于 issue 评论；CONTEXT.md 和 ADR 只吸收其中的词条级边界。一旦一张地图被标为「已被取代」并关闭，后续 agent 会把它整条谱系当历史不再读，评论里的操作性决定（界面语义、流程、默认值、数值档位）就等于丢失。判定规则：**关闭或重画任何地图之前，逐票把决议评论与 CONTEXT/ADR 做对照，把「兼容并存」与「显式矛盾」分开写进新地图；不要用票号或日期先后默认裁决。** 「取代」措辞要慎用——两张地图更常见的关系是补充。

补上裁决还不够，**替代关系必须标回旧票**，不能只写进新地图：读者从搜索、外链和 ADR 引用直接落到旧票，不会先读新地图。四条已执行验证的记法：

1. **旧票正文与原决议评论一律不改写**，替代关系以追加评论表达，原始决议保持可读；旧票已关闭也不重开。
2. 某条旧决议「重新生效」的标注，放在**当初盖过它的那张票**上，而不是被恢复的那张票上——读者是从盖过它的票追过来的，被恢复的票本身从未被就地推翻。
3. 两票**直接矛盾时两侧都标**，并在两侧写同一句裁决与同一个胜出方；只标一侧的话，从另一侧进来的读者仍会读到作废的措辞。
4. 他人撰写的决议里的失效链接，用**独立评论发布更正并声明以更正为准**，不就地改写他人正文——即使有仓库权限。

## Boundaries

- 适用于用 GitHub issue 作 wayfinder 地图、决议写在评论、文档只做词条级记录的项目；若决议直接写进 ADR/文档则风险小得多。
- 不是要求把每条决议都搬进 ADR：离开产品范围的决定（见 #37 Out of scope）可以明确放弃，但放弃要写下来。
- 四条记法针对**旧票已关闭**的追溯性标注；重画时旧票若仍开着，直接改正文更省事，不必走评论。
- 「标回旧票能被读者找到」这一层尚未被后续 agent 的实际检索验证，只验证了写入侧可执行。
