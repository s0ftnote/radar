Radar · 架构与流程

Radar 只搬东西，
不动脑子。

动脑子的是你自己的 Agent。这一条决定了下面所有事情长什么样——谁存什么、谁调模型、谁写报告、Web 上还剩几个页面。

全景

一张图看完：东西从哪进来、存在哪、谁去动它、最后去了哪。

那条线

整套东西只有一条重要的分界线。左边是一台永不下班的笨机器，右边是一个聪明但只在你叫它的时候才在的脑子。

东西从哪来

来源分三档。这一档同时回答了两件事：要不要你配东西，以及谁负责去采。

装好即用 Radar 自己采

RSS/Atom、GitHub、V2EX、YouTube 这类不用登录的。装好实例就开始采，一个字不用配。

配置后解锁 Agent 采完推进来

Reddit、B 站、小红书、Twitter 这类要登录态的。Radar 不写适配器、不保管你的 Cookie——你的 Agent 用自己的工具采完，推给 Radar（ADR 0011）。

够不着 谁也采不了

灰着摆在那儿，作为「我们没覆盖这块」的诚实表达。不写免责声明。

传送带

采进来的东西排成一条队。Radar 只决定先看哪条，永远不决定什么算相关。

一次判断长什么样

不是一个分数，是一段说得清的话。判为不相关也要写清为什么淘汰——你问「这条为什么没给我」，得答得出。

是什么这条内容讲了什么
凭什么依据在哪，可回链
哪里不确定别装作全都知道
为什么给你对着你的 Brief 说

拆成四块，是为了出报告的时候能机械组装，不必去解析别人写的散文。Radar 存四个字符串，照样不理解内容。

三份 Skill，三个时机

装进你 Agent 的是三份技能，各自在不同的时候自己醒过来。

判断角色

你说「跑一遍 Radar」。先把要推的内容推进去，再 radar pending 一次取齐工作包，判完写回。

取数角色

你说「出个周报」「写进 Obsidian」。取还没送到这个去处的判断，输出，标记送达。

管家角色

你说「改一下关注点」「这条没意思」「加个来源」。它得认得出随口一句也是反馈。

从零开始，一遍走完

没有向导、没有配置页、没有「首次设置」。第 1 期和第 20 期在 Radar 眼里完全一样。

  1. 你说一句话「我想持续知道 AI 产品的用户在抱怨什么」你 → 管家角色
  2. 管家写下 Brief一段自然语言，不给你看条文让你校对——人只在面对具体条目时判断才可靠管家角色
  3. 立刻催一次采集radar collect --now。装好那会儿其实已经在采了，这一下是补齐管家角色 → Radar
  4. Radar 排队去重、排序。没有策略时按新鲜度加端点保底配额Radar
  5. 判断角色跑第一遍取工作包，判，写回。这就是「我先跑一遍你看」——不是特殊路径，就是正常的第一次判断角色
  6. 你在具体条目上说要不要「这种别再给我了」——管家把它写成反馈，此后每个工作包都原样带上你 → 管家角色
  7. 之后就一直这样Radar 一直采一直排；你想看的时候叫 Agent 跑一遍、出一份循环

Web 上只剩一张页

来源页，就是首页。没有第二个页面。

页面上有

渠道分组的来源清单、每个端点是正常/失败/等推送、实例级停用开关、粘个网址加源，以及唯一一处设置（你的 RSSHub 地址）。

页面上没有

Brief 列表、Brief 正文、判断台、报告台、队列仪表盘。这些要么在对话里，要么不存在。

为什么还留着它

因为「看」——几十行来源清单在对话里逐条念出来很糟，一眼扫完的页面赢。改反而是顺带的（ADR 0013）。

三条不会变的

Radar 不调模型

没有 BYOK、没有 Plan、没有「模型不可用」这种状态。key 在你的 Agent 里，AI 全在那边（ADR 0009）。

Radar 不丢内容

只排序，从不按规则筛掉。关键词只能加减分，不能用来排除（ADR 0010）。

Radar 不拥有沉淀

它只存自己运转要用的东西。知识去你自己的 Obsidian / Notion，由 Agent 写入——Radar 不知道它存在。
