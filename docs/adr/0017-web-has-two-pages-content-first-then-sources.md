# Web 上有两张页：先是内容，然后才是来源

内容页是首页，来源页移到 `/sources`，顶上两个字来回切。ADR 0013 把 Web 收到只剩一张来源页，那一步走过头了：装完 Radar 打开浏览器，看到的是「这台机器够得着哪些网站」，而用户想知道的是「它替我攒下了什么」。来源页答的是覆盖范围，内容页答的是收成——先看收成。

内容页是**一条流加筛选**，不是三个区块。三档——`给你看`、`判过没给`、`还没轮到`——不是三种处理结果，是同一条内容走到哪儿了：队列里的随时会变成前两档，回捞重判会让判过的退回队列。写成固定区块，页面就要不断解释「这条怎么跑到那边去了」；写成筛选，档就只是当前视图的一个条件。筛选做成链接而不是脚本：刷新即最新，每一种视图都留得住一个网址，页面上一行 JS 都不用。

内容页上摆出判断的四问原文（这是什么 / 凭什么这么说 / 哪里还不确定 / 为什么给你看），判不相关的也摆出淘汰理由。**「被过滤掉」在 Radar 里不存在**——只排序不丢弃（ADR 0010），所以那一档写的是「判过没给」，理由跟着，你随时能追问。

页面上多了一个写动作：在一条判断上说「有用 / 没用」。ADR 0013 的「看归网页、改归对话」保留，这两个按钮不算破例——它写的不是配置，是**你对这一条的话**，而那句话正是下一期判断的上下文（`feedback`）。看到一条没用的东西时人就在页面上，让他为这一句话切回对话，那句话多半就不会被说出来。处置标签本来由 Agent 归纳，页面上没有打字的地方，所以这两个按钮固定写死 `useful` / `not_useful`；更细的话照样跟 Agent 说。说过的话摆在条目旁边，同一条不会被反复点。

## Consequences

- ADR 0013 里「Brief 列表、Brief 正文、队列深度与最近判断时间全部不做」作废。队列深度与上次判断时间回到页面上，作为 Brief 的一行状态（#44 说它是给取数角色用的机械事实，那不妨碍它同时是给人看的一行）。
- Brief 级纳入仍然不上页面。它在读侧生效，所以没被这条 Brief 纳入的端点，内容不出现在内容页里；要改还是跟 Agent 说。ADR 0013 怕的「一张清单变成一个控制台」在这里依然成立。
- 内容页一次显示最近 200 条，截断时说一句。上限是页面的事，不是领域的事——Radar 一条都不丢。
- 一条 Brief 都没有时，内容页说的是「跟你的 Agent 说一句就有了」，不给按钮。首期试用仍然全程在对话里（ADR 0013 的那条结论没变）。
