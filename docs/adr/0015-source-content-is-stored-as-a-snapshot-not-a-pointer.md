# 来源内容存正文快照，不存指针

Radar 采集一条来源内容时，把当时的正文一起存下来，而不是只存标题、摘要和地址。原始地址照样留着供用户回访，但判断引用的证据是本地那份快照。

理由是整条证据链的终点不在 Radar 里。判断的「凭什么」引用 Signal，Agent 把判断沉淀进用户知识库之后，Obsidian 里那条笔记还能不能被核查，完全取决于快照在不在——存指针等于把「你随时能翻到底、能问这条为什么没给我」这个承诺外包给了源站的存续意愿，而删帖、改版、加登录墙是常态不是意外。这个决定还是不可逆的：当初没存，事后补不回来。替代方案是只存标题、摘要和地址，否掉的理由是摘要是二手的——「凭什么」这一块要引用的是原话。

要正视的张力在许可上：出厂来源目录的准入第一条是「许可允许机器读取」，而「读」与「存一份副本」不是一回事。仍然选择存，前提是 Radar 当前的形态——本地、单用户、不分发、不对外提供内容服务，与浏览器缓存同形；用户完整导出带走的也只是他自己那一份。这个前提变了，这条决定就得重新审视。

## Consequences

- 快照只存文本。图片、视频、附件留地址不留副本。
- 快照是采集那一刻的，不追更新。源站后来改了 Radar 不知道，也不该知道——当初的判断依据的就是那一版。
- 保留窗口是队列的时间规则，作用于「还等不等 Agent 来判」，不作用于快照。移出队列不删内容（ADR 0010），快照跟着内容留。
- 配置后解锁渠道由 Agent 采集推送（ADR 0011），推的时候就得带正文；只推地址的推送是不完整的推送。
- 存储随时间单调增长。这是用户自己的磁盘，不是我们的成本，也不构成丢弃内容的理由。
- 本决定不给 Radar 任何对外提供内容的资格。一旦出现托管形态或多用户形态，前提失效，须重新决定。
- 出厂来源目录的准入条件不变：许可存疑的端点仍然不进目录，存不存快照与能不能采是两个问题。
